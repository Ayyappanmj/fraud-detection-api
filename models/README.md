# models/

Model artifacts are generated by `python -m src.train` and are **not committed** (see `.gitignore`).

| File | Purpose |
|---|---|
| `model.joblib` | Isolation Forest bundle |
| `baseline_logreg.joblib` | Supervised Logistic Regression baseline (not served by the API) |
| `metadata.json` | Version, threshold, feature schema, SHA-256 of `model.joblib`, training info |
| `metrics.json` | Validation and test metrics |
| `reference_stats.json` | Training-feature statistics used by drift monitoring |
| `eda_summary.json` | Exploratory data analysis summary |

The API refuses to load `model.joblib` if its SHA-256 does not match `metadata.json`.

## Versioning and safe promotion

1. Train a **candidate** into a separate folder: `python -m src.train --out-dir models_candidate`.
   The quality gate (`--min-pr-auc`) aborts without writing artifacts if the candidate is too weak.
2. Compare `models_candidate/metrics.json` with the current `models/metrics.json` on the same held-out data.
3. Run the tests. Start the API with `MODEL_DIR=models_candidate` locally and smoke-test `/predict`.
4. Promote by replacing `models/` (or the deployed build), keeping the previous folder for rollback.
   The version string `1.0.0-<sha8>` changes automatically with the model file.
5. For real use, store artifacts in a registry/object store or GitHub Release - not in git history.
